Case Study 01 · Infor Birst · Navigation + Filtering UX
Accessibility Dashboard & Smart Filter Panel
My role: Designer Associate — Sole designer on this feature end-to-end
Live · Shipped Navigation Design Filter UX Accessibility Form Patterns Figma
🎯
01
Project Overview & Context
Infor Birst is an enterprise Business Intelligence platform used by large organizations to visualize and analyze their data. As part of a broader accessibility initiative, I was tasked with designing two interconnected systems: a redesigned side navigation for the dashboard experience, and a "Create Filter" panel that lets users define data filters for their reports. This was one of my first end-to-end feature assignments as a Designer Associate at Infor.
🔍
02
User Research & Discovery — The "Why"
Working with the product team, I analyzed how enterprise users navigated between dashboards and applied filters. Key pain points emerged:
  • Users were creating duplicate filters accidentally — no system feedback existed to catch this
  • The navigation lacked clear hierarchy, making it hard to jump between key dashboard views quickly
  • Filter creation involved too many steps with unclear labeling, causing drop-off and support tickets
  • Accessibility was under-addressed — color contrast, keyboard navigation, and ARIA labels needed attention

Core insight: Enterprise users need speed and confidence. Any friction in navigation or filtering disrupts analytical workflows and erodes trust in the tool.

🗺
03
Ideation & Information Architecture
I mapped the full navigation structure of the dashboard, identifying which sections needed top-level vs nested placement. For the filter panel, I drafted a form flow that reduced cognitive load by grouping related controls (filter source, aggregation, date type) into a logical sequence. I explored three layout patterns before settling on a right-side drawer panel that preserved dashboard context while editing filters.
  • Mapped IA for side nav: Key Drivers → Quantity Overview → Discount Overview → Units in Stock
  • Designed filter panel as a step-through form: Filter On → Aggregation → Date Type → Default Value
  • Added a real-time duplicate detection banner — shown inline before saving
🔄
04
Iterative Design & Testing — The Evolution
I went through three rounds of design review with engineering and product leads. Key iterations included:
  • Round 1: Basic nav skeleton and filter form — feedback: needed clearer section labels and better toggle for "Allow Multiple Values"
  • Round 2: Introduced the orange duplicate-filter warning banner and refined the Basic/Advanced tab structure in the filter panel
  • Round 3: Final accessibility pass — checked color contrast ratios, added focus states, improved form field spacing for keyboard navigation
✨
05
Final UI & Visual Design — The "Wow" Factor
The final design featured a clean tab-based nav with high-contrast selected states, a compact and scannable filter creation panel, and a smart validation system. The warning banner ("A filter with the same logic already exists") appears contextually — preventing errors without interrupting the user's flow. The "Allow Multiple Values" toggle and default value input field are revealed progressively to avoid overwhelming users upfront.

Design principle applied: Progressive disclosure — show only what's needed at each step. Complexity lives beneath the surface until the user is ready for it.

📈
06
Impact, Metrics & Takeaways
↓ Dupes
Duplicate filter creation reduced via inline validation warning
AA
WCAG AA accessibility compliance achieved on filter controls
Live
Shipped to production and used by real Infor enterprise customers
  • Learned to design for enterprise-scale complexity — thousands of users, varied technical literacy
  • Deepened my understanding of accessibility-first design in data-heavy interfaces
  • This project taught me that the best UX often comes from removing steps, not adding features
Case Study 02 · Infor Birst · Chart Controls UX
Chart Settings Panel & Zoom Level Interaction
My role: Designer Associate — Owned the Zoom Level feature design end-to-end
Live · Shipped Interaction Design Zoom Controls Chart Settings Toggle Patterns Data Viz
🎯
01
Project Overview & Context
Infor Birst's bar chart component had a settings panel with various toggles for controlling how data was visualized. My task was to design the Chart Settings flyout panel and specifically own the Zoom Level feature — a new capability that would allow users to zoom in and out on chart data directly within their dashboard, without needing to leave context or open a fullscreen view.
🔍
02
User Research & Discovery — The "Why"
Analysts working with time-series data in Birst often needed to zoom into specific date ranges on bar charts. The existing pattern required them to navigate away or apply manual date filters — breaking their analytical flow. Research and stakeholder interviews revealed:
  • Power users wanted chart-level zoom controls without leaving the dashboard view
  • The settings panel had no discoverability — users didn't know many toggles existed
  • Zoom as a toggle (on/off) felt more appropriate than always-visible controls, to keep the chart UI clean

Core insight: Users want control without clutter. The zoom controls should only appear when the user signals intent — triggered by enabling the toggle.

🗺
03
Ideation & Information Architecture
I explored two models for where zoom controls should appear once enabled: overlaid on the chart canvas, or docked in the chart toolbar. I chose the top-right toolbar placement — consistent with other Birst chart actions — and designed the toggle as the activation mechanism within the settings panel. The settings panel itself was organized into logical clusters: Measure display options (Stack/Group/Percent), Color control, and Behavior toggles (Lock Axes, Delay Charting, Zoom Level).
🔄
04
Iterative Design & Testing — The Evolution
  • V1: Zoom controls as floating buttons over the chart — feedback: felt intrusive and covered data
  • V2: Zoom controls in the settings panel itself — feedback: not discoverable once panel was closed
  • V3 (final): Zoom toggle in settings panel → activates +/− controls in the chart top-right toolbar. Clean, contextual, consistent with Birst's existing toolbar pattern
  • Also iterated on the "on" state visual for the toggle — using Birst's blue active color to signal enabled state clearly
✨
05
Final UI & Visual Design — The "Wow" Factor
The final design is a clean settings flyout with grouped icon-label toggles. Enabled states glow blue (Birst's system accent). When Zoom Level is toggled on, the chart view immediately surfaces + and − controls in the top-right toolbar — letting users zoom in and out of the date axis without any page navigation. The series legend and axis labels update in real-time as users zoom, reinforcing context.

Design principle applied: Visibility of system status — the chart toolbar immediately reflects the toggle state, giving users instant feedback that their action took effect.

📈
06
Impact, Metrics & Takeaways
New
First zoom capability shipped in Birst's chart component library
0 ctx
Zero context switches — zoom works without leaving the dashboard
Live
Shipped to production across Birst enterprise customers
  • Learned how to design progressive interaction — features that activate on demand rather than always being visible
  • Understood the value of platform consistency — new features should feel native, not bolted on
  • Working within a design system taught me the discipline of reusing patterns before inventing new ones
Case Study 03 · Infor Birst · Space Management
Impact Flow — Data Lineage Visualization
My role: Designer Associate — Designed the full Impact Flow screen from scratch
Live · Shipped Data Lineage UX Graph Visualization Information Architecture Admin Tools Figma
🎯
01
Project Overview & Context
Impact Flow is a data-lineage visualization feature built for Infor Birst's analytics platform. It gives users — primarily data admins and analysts — a bird's-eye view of how columns, tables, sources, and reports connect across their entire workspace. More importantly, it answers the question that every data admin dreads: "If I change this, what breaks?" Before Impact Flow, there was no way to trace upstream or downstream dependencies visually. Users had to mentally map connections or discover breakages after they'd already happened. My job as Designer Associate was to design this screen entirely from scratch — no prior reference existed in the product.
🔍
02
User Research & Discovery — The "Why"
Through stakeholder discussions and proxy research from enterprise admin users, we uncovered a critical workflow gap. Data admins managing large Birst environments were operating blind when it came to dependency management:
  • Modifying a source column or table could silently break downstream reports and dashboards — with no warning
  • Admins had no tool to answer "which reports depend on this subject area or filter?" before making changes
  • The existing list-based views in Space Management showed objects in isolation — relationships were invisible
  • Large workspaces with multiple subject areas made it impossible to mentally track connections without a visual aid
  • When something broke, root-cause investigation was slow — admins had to manually trace back through configs

Core insight: Data admins don't just manage objects — they manage relationships. A list can show what exists; only a graph can show what depends on what. The cost of a blind change in enterprise BI is high: broken dashboards, missed reports, and lost trust from business stakeholders.

🗺
03
Ideation & Information Architecture
The central design challenge was: how do you represent a complex multi-level dependency chain — connectors → tables → columns → subject areas → filters → reports — in a way that's readable, scannable, and actionable? I explored three layout models:
  • Force-directed graph — organic, but too chaotic for large workspaces; hard to read directionality
  • Hierarchical tree (top-down) — clear levels but awkward for wide dependency chains
  • Left-to-right flow diagram (chosen) — mirrors how data admins mentally model pipelines: source on the left, output on the right. Directional, readable, scalable
I structured the IA as a 4-level node chain: Connector → Subject Area (e.g. Orders) → Filter (e.g. Net Profit) → Reports & Dashboards. Each level uses a distinct node icon so users can instantly identify the object type. The left panel provides a subject area navigator with search — scoping the graph to one area at a time for large workspaces. The toolbar gives zoom, refresh, and a "Shared connections only" toggle to surface cross-subject-area dependencies.
🔄
04
Iterative Design & Testing — The Evolution
This screen went through four major design iterations before reaching its final state:
  • V1 — Full graph, no filtering: All nodes and connections rendered at once. Feedback: visually overwhelming for real-world workspaces with dozens of subject areas and hundreds of reports
  • V2 — Left panel subject area filter added: Dramatically improved focus. Users could scope the graph to one subject area. New feedback: still needed a way to see cross-space shared connections without switching subject areas
  • V3 — "Shared connections only" toggle: A toolbar toggle that filters the graph to show only objects shared across multiple subject areas — a critical admin use case for auditing shared data dependencies
  • V4 — Active node selection system: Clicking a node highlights it in blue and dims unconnected nodes — giving users laser focus on one object's lineage. The × dismiss restores the full graph. Also refined node label truncation rules and spacing for dense graphs
✨
05
Final UI & Visual Design — The "Wow" Factor
The final Impact Flow screen is a calm, white-canvas graph that breathes — nodes are well-spaced, connection lines are clean, and the visual hierarchy makes the data flow immediately readable from left to right. Each node type (connector, subject area, filter, report) carries its own icon for instant identification. Selecting a node such as "Net Profit" activates it in Birst's blue and draws focus to only its direct upstream and downstream connections — the rest of the graph fades. The breadcrumb trail (Admin / Space Management / Impact Flow) anchors the admin in their navigation context at all times.

Design principle applied: Focus + context — always show the user where they are and what's connected to what, while making it trivial to zoom into a single object's lineage. The design answers "what breaks if I change this?" in one click.

📈
06
Impact, Metrics & Takeaways
First
First-ever data lineage visualization shipped in Infor Birst's platform history
1 click
Admins can now trace full connector-to-report dependency chains in a single click
0 blind
Eliminated blind changes — admins see downstream impact before touching anything
  • Designing a graph-based interface from scratch taught me that spatial layout is itself a design decision — left-to-right flow communicates directionality that a list never could
  • This project sharpened my ability to handle progressive complexity — the graph needed to work for a workspace with 3 reports and one with 300
  • I learned that the most valuable features in enterprise tools are often the ones that prevent problems, not just solve them — Impact Flow gives admins confidence before they act
  • Working on a genuinely novel screen (no prior reference in the product) built my confidence in designing from first principles
Case Study 04 · Infor Birst · Analytics Platform
Gauge Chart & Color Palette Segment System
My role: Designer Associate — Owned gauge chart component and color system design
Live · Shipped Gauge Chart Design Color Systems Contextual Tooltips Disabled States Data Viz
🎯
01
Project Overview & Context
Infor Birst's analytics platform supports a wide range of chart types for data visualization. The gauge chart — used to display KPIs like revenue targets, sales quotas, and stock levels — needed a new segment configuration system. Each segment on the gauge arc represents a performance range (e.g., low/medium/high), and users needed to assign both values and colors to each segment. The challenge was that Birst also had a global color palette system, which could conflict with per-segment manual color choices.
🔍
02
User Research & Discovery — The "Why"
Feedback from enterprise users and internal product reviews surfaced key friction points with the existing gauge chart:
  • Users were confused when their manual segment color choices were being overridden by the global palette — with no explanation
  • The segment panel had no clear link between the color picker state and the palette dropdown
  • Business users without technical knowledge couldn't tell why a control was disabled
  • The gauge chart visual itself lacked the polish expected for enterprise customer-facing dashboards

Core insight: Disabled UI without explanation creates confusion, not clarity. Every disabled state needs a "why" — delivered at the point of interaction.

🗺
03
Ideation & Information Architecture
I mapped the logic tree for color control: if a palette is selected in the dropdown, individual segment color pickers should be disabled — but not silently. I designed a contextual tooltip system that appears on hover of any disabled color swatch, explaining: "Colors are controlled by the palette. Toggle off color palettes to enable." I also structured the segments panel as a numbered list (#1, #2, #3, #4) with each segment having a name field, color swatch, and value input — keeping the relationship between name, color, and value clear at a glance.
🔄
04
Iterative Design & Testing — The Evolution
  • V1: Color pickers simply greyed out when palette was active — no explanation. User testing showed confusion
  • V2: Added a banner at the top of the panel explaining palette override — feedback: too far from the point of confusion
  • V3 (final): Inline tooltip on each disabled swatch — contextual, proximate, and non-intrusive. Users understood immediately
  • Also iterated on the gauge chart arc design — segment widths, needle design, and revenue label placement went through 4 visual revisions
✨
05
Final UI & Visual Design — The "Wow" Factor
The final design features a clean arc gauge with four color-coded segments, a pointer needle, and a central revenue value display. The segments panel on the right lists each segment with its name, color swatch (disabled when palette-controlled), and numeric value. The hover tooltip on disabled swatches delivers exactly the right explanation at exactly the right moment. The top-level warning banner provides secondary context for users who want the fuller picture.

Design principle applied: Proximity of feedback — help should appear where the confusion arises, not in a distant banner or documentation page.

📈
06
Impact, Metrics & Takeaways
↓ Confusion
Inline tooltip eliminated the most common "why is this disabled?" support query
✓ Consistent
Color system now behaves predictably across all chart types in Birst
Live
Shipped to enterprise users on the Birst analytics platform
  • Deepened my understanding of designing for system state — when controls are disabled, the design must explain why
  • Learned the nuance of color system design in enterprise tools — global vs local control is a real UX challenge
  • This project reinforced that micro-decisions (like tooltip placement) have outsized impact on user confidence
